# EA News Filter Architecture

สกิลนี้สรุปแนวทางการสร้างและหลักการทำงานของ "News Filter" (ระบบป้องกันการเทรดช่วงมีข่าว) ซึ่งเป็นฟีเจอร์บังคับที่มีใน Expert Advisor (EA) ระดับโปร เพื่อป้องกันพอร์ตจากสภาวะ Slippage, Spread ถ่าง, และ Stop-hunting

## When to Use

- "แล้วปกติ ea อื่นใช้วิธีไหนกรองข่าว ช่วยหาข้อมูล แล้วนำมาวิเคราะห์"
- เมื่อต้องการสร้างระบบ News Filter ลงใน MT5 EA หรือ Python Trading Bot
- เมื่อต้องการทำความเข้าใจความเสี่ยงของการใช้ Web Scraping ดึงข่าว

## Quick Reference

- **Rule 1:** บล็อกเฉพาะการ "เปิดออเดอร์ใหม่ (Entries)" ห้ามบล็อกการขยับ SL/TP หรือการปิดออเดอร์
- **MQL5 Native Approach:** ใช้ `Economic Calendar API` ของ MT5 (เร็วที่สุด และเสถียรสุด)
- **Third-Party Approach:** ใช้ `WebRequest` ดึงไฟล์ CSV/XML จากเว็บข่าว (ต้องเปิด Allow DLL)
- **Volatility Approach:** ใช้ `ATR Spike` ตรวจจับความผิดปกติจากกราฟโดยตรง (ไม่ต้องง้ออินเทอร์เน็ต)

## การวิเคราะห์แนวทางการสร้าง News Filter

จากข้อมูลและสถาปัตยกรรมของ EA ในตลาด (เช่น XAUBOT, ASQ News Filter) พบว่านักพัฒนา EA มีวิธีการสร้างระบบหลบข่าวอยู่ 3 แนวทางหลัก ดังนี้:

### 1. Web Request API (แนวทางยุคเก่า / นิยมใน MT4)
- **วิธีการ:** EA จะยิง HTTP Request ไปดึงตารางข่าว (XML/CSV) จากเว็บไซต์หลัก เช่น ForexFactory หรือ Investing.com แล้วนำมาคำนวณเวลากับเวลาเครื่อง
- **ข้อดี:** ได้ข้อมูลข่าวล่วงหน้าแม่นยำ (รู้ว่าจะเกิดเหตุการณ์อะไร)
- **ข้อเสีย (จุดตาย):** 
  - ต้องเปิดสิทธิ์ `Allow DLL imports` และเพิ่ม WebRequest URL เสมอ (ทำให้นักลงทุนหลายคนติดตั้งไม่ผ่าน)
  - เซิร์ฟเวอร์ VPS มักจะบล็อก WebRequest
  - ถ้าระบบเว็บต้นทางเปลี่ยนหน้าตา (Layout) หรือล่ม EA จะเอ๋อและพาพอร์ตพัง
  - **ไม่ผ่านการทดสอบใน MQL5 Market Validation**

### 2. MT5 Native Economic Calendar (แนวทางมาตรฐานยุคใหม่)
- **วิธีการ:** ใช้ไลบรารีมาตรฐานของ MQL5 ที่ชื่อ `Economic Calendar API` ซึ่งเชื่อมต่อข้อมูลข่าวกับเซิร์ฟเวอร์ของโบรกเกอร์โดยตรง 
- **ข้อดี:** 
  - ไม่ต้องใช้ `WebRequest` ไม่ต้องเปิด DLL 
  - สามารถระบุได้ว่า จะหลบเฉพาะข่าวระดับ High Impact ของสกุลเงิน USD หรือ EUR เท่านั้น
  - ทำงานใน Strategy Tester ได้
- **โครงสร้างลอจิก (Logic Flow):**
  1. EA โหลดตารางข่าวล่วงหน้ามาเก็บไว้ใน Cache
  2. เมื่อมีสัญญาณเทรด EA จะเช็คว่า `[เวลาปัจจุุบัน]` อยู่ในช่วง `[เวลาข่าว - N นาที]` ถึง `[เวลาข่าว + N นาที]` หรือไม่ 
  3. ถ้าใช่ -> ระงับการยิงออเดอร์ใหม่

### 3. Price Action Volatility Filter (แนวทางสาย Quant / Python)
- **วิธีการ:** ไม่อ่านปฏิทินข่าวเลย แต่ให้ระบบอ่าน "แรงสั่นสะเทือน" จากกราฟโดยตรง (คล้ายแผ่นดินไหว) มักใช้ `ATR (Average True Range)` บน Timeframe สั้นๆ (M1 หรือ M5)
- **ข้อดี:** 
  - เขียนโค้ดง่ายที่สุดและเสถียรที่สุด 
  - หลบข่าวลับ (Unplanned Events) หรือข่าวนอกตาราง (เช่น ทวีตของประธานาธิบดี, สงครามกะทันหัน) ได้ด้วย
- **โครงสร้างลอจิก:** 
  - ถ้าระยะห่างของ High-Low ปัจจุบัน กระชากสูงกว่า `ATR เฉลี่ย * 3.0 เท่า` -> แปลว่ามีข่าว หรือมีสถาบันเทขาย -> สั่งบอทเข้าสถานะ `PAUSED` เป็นเวลา 30 นาที

## Pitfalls & Best Practices

- **The Golden Rule:** ไม่ว่าคุณจะใช้ระบบกรองข่าวแบบไหน **จงบล็อกแค่คำสั่งซื้อขายใหม่ (Entry) เท่านั้น** ห้ามนำระบบ News Filter ไปบล็อกฟังก์ชัน Trailing Stop, Break-Even, หรือเงื่อนไข Take Profit/Stop Loss เด็ดขาด เพราะช่วงข่าวกระชาก คือช่วงที่ระบบต้องทำงานเร็วที่สุดเพื่อรักษาพอร์ต
- **Timezone Hell:** ปัญหาคลาสสิกของการดึง API ข่าว คือเวลาในปฏิทินข่าว (GMT) ไม่ตรงกับเวลาของเครื่องคอมพิวเตอร์ (Local Time) และไม่ตรงกับเวลาของโบรกเกอร์ (Server Time) ระบบ News filter ที่ดีต้องแปลงทุกเวลาให้ตรงกับ **Server Time** ของ MT5 ก่อนประมวลผล

## Verification
- หากใช้แนวทางที่ 2 (MQL5 Native) บน MT5 ระบบจะต้องสามารถวาดเส้นแนวตั้ง (Vertical Lines) บนกราฟเพื่อแสดงตำแหน่งของข่าวล่วงหน้าได้
- หากใช้แนวทางที่ 3 (ATR Volatility) ระบบบอทจะต้องปรินต์สถานะ `Status: PAUSED (News Detected)` ทันทีที่มีแท่งเทียนยาวผิดปกติเกิดขึ้น
