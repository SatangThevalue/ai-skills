- **String Interpolation & F-String Braces Pitfall:** เมื่อเขียน Prompt หรือข้อมูล JSON string ใน python F-string (เช่น `f"Return JSON: {'amount': 0}"`) ให้ระวังปัญหากลืนคำสั่งปีกกา `{}` ซ้อนกัน ซึ่ง Python compiler จะตีความปีกกาเป็น format tag และทำให้โยนข้อผิดพลาด `ValueError: Invalid format specifier` ในขณะรันเสมอ ให้ใช้วิธีการ escape ปีกกาด้วย double braces (เช่น `{{ }}`) หรือหลีกเลี่ยงการใช้ f-string ไปใช้ string concatenation แบบปกติแทนเพื่อความปลอดภัย
- **Docker Compose Port Binding Mismatch:** ตรวจสอบ docker container mapping ทุกครั้งผ่าน `docker ps` หรือ `docker inspect` เพื่อดูว่าพอร์ตด้านในของ container ถูก map ไปที่ host port อะไร (เช่น Database ใน docker ใช้งานพอร์ต 5432 ด้านใน แต่ออกพอร์ต 5433 ด้านนอกเครื่อง host) การเชื่อมโยงจาก host config ต้องระบุพอร์ตเครื่อง host ที่แท้จริง (5433) เสมอ มิฉะนั้นจะเชื่อมต่อล้มเหลวด้วย error "password authentication failed" หรือ "connection refused"
- **Webhook Reply Callback requirement:** ในการออกแบบระบบ Webhook สำหรับ LINE Bot ห้ามทำเพียงแค่การ parse ข้อมูลและบันทึกลง database เท่านั้น จะต้องมีกลไกส่งข้อความตอบกลับผู้ใช้ผ่านทาง API เสมอ โดยการนำเข้า `Configuration, ApiClient, MessagingApi, ReplyMessageRequest, TextMessage` จาก `linebot.v3.messaging` เพื่อส่ง payload ตอบกลับทันทีที่ทำรายการเสร็จ
- **Uvicorn restart crash on missing params**: ระวังการเรียง parameter ใน Python function/FastAPI path operation function ห้ามเอา parameter ที่ไม่มี default (เช่น `session: SessionDep`) ไปไว้หลัง parameter ที่มี default (เช่น `admin: AppUser = Depends(get_current_admin)`) เพราะจะทำให้อินทิเกรเตอร์หรือคอมไพเลอร์ฟ้อง `SyntaxError: non-default argument follows default argument` และ uvicorn จะ crash ทันที
- **BackgroundTasks and LINE showLoadingAnimation**: Use `asyncio.to_thread` for executing synchronous AI logic (like LangChain) inside the background task. Avoid using `asyncio.run()` directly within the event handler inside the main loop, as it triggers "RuntimeError: asyncio.run() cannot be called from a running event loop". Use `asyncio.get_running_loop().create_task()` instead if triggering from a sync handler.

- **String Interpolation & F-String Braces Pitfall:** เมื่อเขียน Prompt หรือข้อมูล JSON string ใน python F-string (เช่น `f"Return JSON: {'amount': 0}"`) ให้ระวังปัญหากลืนคำสั่งปีกกา `{}` ซ้อนกัน ซึ่ง Python compiler จะตีความปีกกาเป็น format tag และทำให้โยนข้อผิดพลาด `ValueError: Invalid format specifier` ในขณะรันเสมอ ให้ใช้วิธีการ escape ปีกกาด้วย double braces (เช่น `{{ }}`) หรือหลีกเลี่ยงการใช้ f-string ไปใช้ string concatenation แบบปกติแทนเพื่อความปลอดภัย

## Pitfalls
- **UX/Loading Animation:** ใน SDK v3 สามารถใช้ `line_bot_api.show_loading_animation(ShowLoadingAnimationRequest(chatId=user_id, loadingSeconds=40))` เพื่อแสดงจุดไข่ปลากระพริบ (Typing indicator) ระหว่างรอ AI ประมวลผลได้ โดยสามารถระบุระยะเวลาที่ต้องการได้ (เช่น 40 วินาที)
- **Onboarding & Authentication Flow:** สำหรับระบบ AI Bot ที่พ่วงระบบสมาชิก (เช่น Better-Auth) ควรตรวจสอบการมีอยู่ของบัญชี LINE ในตารางเชื่อมโยง (เช่น `line_account`) ก่อนเสมอ หากไม่พบข้อมูล ให้ส่ง LINE Flex Card เสนอการเชื่อมโยงบัญชี/สมัครสมาชิกกลับไปทันทีเพื่อบังคับ Onboarding
- **AI Transaction Classification:** ควรตั้งค่า AI prompt ให้ระบุ flag ความเป็นธุรกรรมการเงินให้ชัดเจน (เช่น `is_transaction: boolean`) เพื่อให้ระบบหลังบ้านคัดกรองคำพูดทั่วไป (เช่น "สวัสดีครับ") ออกจากการประมวลผลระบบบัญชีโดยอัตโนมัติ เพื่อป้องกันฐานข้อมูลสกปรก
- **RuntimeError: asyncio.run():** ห้ามใช้ `asyncio.run()` ภายใน `@handler.add` ของ FastAPI เด็ดขาด เพราะจะเกิด RuntimeError เนื่องจากมี event loop รันอยู่แล้ว ให้ใช้ `loop.create_task()` แทน

- **Blocking the Event Loop with AI:** LangChain and other LLM calls are often synchronous. If placed directly in the webhook handler without `await asyncio.to_thread()`, they will block the entire FastAPI server, causing other users' requests to queue or timeout.

  - **Workaround:** ให้แยก Task ประมวลผลหนักออกจาก Flow การตอบกลับแบบทันที หรือนำ Push Message API มาทำงานเป็นระบบ Fallback เมื่อการรัน Background Task เกินเวลา

  - **แนวทางปฏิบัติ:** บังคับให้ตรวจสอบ (Sanitize) ทุกตัวแปรที่จะแสดงผลใน Flex Message เสมอ เช่น `safe_note = str(note).strip() if note and str(note).strip() else "-"`
  - **ระบบ Fallback:** เพื่อป้องกันไม่ให้บอทเงียบหายหากโครงสร้าง Flex เสียหาย ให้ครอบบล็อก `try-except` ในส่วนส่ง Flex Message ไว้ แล้วถอยกลับไปส่งข้อความอักษรแบบธรรมดา (Text Message) แทน เช่น `line_bot_api.reply_message(..., messages=[TextMessage(text=fallback_text)])`

  - เมื่อผู้ใช้อัปโหลดรูปภาพสลิป LINE SDK (`MessagingApiBlob.get_message_content(message_id)`) จะต้องทำการดาวน์โหลดไบนารีจาก LINE Server
  - หากรูปภาพถูกอ้างอิงเป็น `message_id` ปลอม/จำลอง (เช่น จาก Playwright specs หรือ mock test script) คำสั่งดึงภาพจะโยน Exception และระบบ backend จะ fallback คืนค่า `is_transaction: False` ส่งผลให้ระบบเข้าใจผิดว่ารูปภาพนั้นไม่ใช่สลิปและปฏิเสธข้อความพร้อมแจ้งเตือนไปยังผู้ใช้ว่า *"ขออภัยครับ รูปภาพนี้ไม่ใช่สลิปการโอนเงิน..."*

- **FastAPI / FastAPI dependencies mismatch:** ใน FastAPI Route handler ที่เป็น `@app.post` หากต้องการระบุ signature header ให้ใช้ `Annotated[str | None, Header(alias="X-Line-Signature")]`
- **Event Loop Blocking (Asyncio RuntimeErrors):** The `handler.handle()` execution from LINE SDK is synchronous and invokes `@handler.add` callbacks synchronously. If running within an async framework like FastAPI, calling `asyncio.run(my_async_func())` inside the event handler will crash with `RuntimeError: asyncio.run() cannot be called from a running event loop`. Instead, retrieve the running loop and spawn a task: `asyncio.get_running_loop().create_task(my_async_func())`. If long-running I/O or AI operations are needed inside that async func, push them to a thread with `await asyncio.to_thread(sync_long_running_func)` to avoid blocking the main event loop.
- **SDK v3 add decorator matching:** ใน v3 `@handler.add` ต้องการคลาส Message Event และ Content Type ที่สอดคล้อง เช่น `MessageEvent` และ `TextMessageContent` หรือ `ImageMessageContent` (ต่างจาก v2 ที่ใช้ `MessageEvent` และ `TextMessage` ใน model/type เดียว)
- **Signature verification fails with 401:** เกิดจาก raw body ถูก parse เป็น JSON หรือ mutate ไปแล้ว หรือ key ใน `.env` มีอักขระพิเศษเว้นวรรค
- **String Interpolation & F-String Braces Pitfall:** เมื่อเขียน Prompt หรือข้อมูล JSON string ใน python F-string (เช่น `f"Return JSON: {'amount': 0}"`) ให้ระวังปัญหากลืนคำสั่งปีกกา `{}` ซ้อนกัน ซึ่ง Python compiler จะตีความปีกกาเป็น format tag และทำให้โยนข้อผิดพลาด `ValueError: Invalid format specifier` ในขณะรันเสมอ ให้ใช้วิธีการ escape ปีกกาด้วย double braces (เช่น `{{ }}`) หรือหลีกเลี่ยงการใช้ f-string ไปใช้ string concatenation แบบปกติแทนเพื่อความปลอดภัย
- **Docker Compose Port Binding Mismatch:** ตรวจสอบ docker container mapping ทุกครั้งผ่าน `docker ps` หรือ `docker inspect` เพื่อดูว่าพอร์ตด้านในของ container ถูก map ไปที่ host port อะไร (เช่น Database ใน docker ใช้งานพอร์ต 5432 ด้านใน แต่ออกพอร์ต 5433 ด้านนอกเครื่อง host) การเชื่อมโยงจาก host config ต้องระบุพอร์ตเครื่อง host ที่แท้จริง (5433) เสมอ มิฉะนั้นจะเชื่อมต่อล้มเหลวด้วย error "password authentication failed" หรือ "connection refused"
- **Webhook Reply Callback requirement:** ในการออกแบบระบบ Webhook สำหรับ LINE Bot ห้ามทำเพียงแค่การ parse ข้อมูลและบันทึกลง database เท่านั้น จะต้องมีกลไกส่งข้อความตอบกลับผู้ใช้ผ่านทาง API เสมอ โดยการนำเข้า `Configuration, ApiClient, MessagingApi, ReplyMessageRequest, TextMessage` จาก `linebot.v3.messaging` เพื่อส่ง payload ตอบกลับทันทีที่ทำรายการเสร็จ
- **Uvicorn restart crash on missing params**: ระวังการเรียง parameter ใน Python function/FastAPI path operation function ห้ามเอา parameter ที่ไม่มี default (เช่น `session: SessionDep`) ไปไว้หลัง parameter ที่มี default (เช่น `admin: AppUser = Depends(get_current_admin)`) เพราะจะทำให้อินทิเกรเตอร์หรือคอมไพเลอร์ฟ้อง `SyntaxError: non-default argument follows default argument` และ uvicorn จะ crash ทันที
- **BackgroundTasks and LINE showLoadingAnimation**: Use `asyncio.to_thread` for executing synchronous AI logic (like LangChain) inside the background task. Avoid using `asyncio.run()` directly within the event handler inside the main loop, as it triggers "RuntimeError: asyncio.run() cannot be called from a running event loop". Use `asyncio.get_running_loop().create_task()` instead if triggering from a sync handler.
