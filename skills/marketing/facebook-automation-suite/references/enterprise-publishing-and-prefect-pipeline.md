# Enterprise Publishing & Zero-Token Prefect Pipeline

Guidelines and patterns for running production-grade Facebook Fanpage publishing with zero LLM token waste, anti-bot timing, and human-in-the-loop controls.

## 1. Zero-Token Prefect Sweeper Architecture

Never use an LLM agent to poll the clock or database. Mechanical polling consumes hundreds of tokens per hour for zero value.
Instead, run an autonomous Prefect flow on a schedule (e.g. every 15 minutes) using native Python:

```python
from prefect import flow, task

@task
def sweep_approved_queue():
    # Queries PostgreSQL for posts that are explicitly approved and due
    sql = """
    SELECT id, page_id, headline FROM facebook_content_evaluations
    WHERE human_approval_status = 'APPROVED_BY_USER'
      AND published_status = 'APPROVED_READY_TO_POST'
      AND (scheduled_at IS NULL OR scheduled_at <= NOW())
    LIMIT 1;
    """
    ...

@flow(name="Facebook Auto-Publisher Sweeper")
def auto_publisher_sweeper():
    target = sweep_approved_queue()
    if not target:
        return "IDLE_0_TOKENS"  # Stays 100% silent, consumes 0 LLM tokens
    ...
```

## 2. Randomized Human-Jitter Timing (Anti-Bot Defense)

Posting at exact clock marks (e.g. `16:30:00`, `19:30:00`) signals automated bot software to Meta's algorithms, triggering algorithmic reach throttling.
Always apply a randomized human jitter offset to scheduled minutes and seconds:

```python
import random
from datetime import datetime, time

def get_human_jitter_time(base_hour: int, start_min: int = 30, end_min: int = 58) -> time:
    """Generates natural human-like posting minutes (e.g. 16:37:42, 19:54:15)."""
    return time(
        hour=base_hour,
        minute=random.randint(start_min, end_min),
        second=random.randint(10, 50)
    )
```

## 3. Human-in-the-Loop Approval State Machine

Content generated by AI must default to a holding state until explicitly approved by the creator.
- `PENDING_REVIEW`: Draft generated, passed quality audit (>=85%), awaiting human inspection.
- `APPROVED_BY_USER`: Explicitly approved via Telegram / dashboard. Only posts in this state are swept by the publisher.
- `REVISION_REQUESTED`: Creator requested surgical edits (Hook rewrite, caption compression, image tweak).
- `REJECTED_BY_USER`: Cancelled; never published.
- `AUTO_PUBLISHED`: Successfully published to Meta Graph API.

*Lazy vs. Active Creator Dynamics:*
If the user does not take action, the system remains dormant. Posts are never auto-published without explicit approval.

## 4. Short Standardized Asset Naming

Do not use verbose or repetitive names inside asset folders (e.g. `page_name_20261001_topic_slug_TPL_001.png`).
Enforce the compact standard:
$$\text{\{YYYYMMDD\}-\{XXXX\}.png}$$
Example: `20261001-0001.png`. All semantic metadata (headline, topic, pillars, metrics) belongs in PostgreSQL, not in the filesystem filename.

## 5. Smart Community Engagement Filtering

Never auto-reply to every comment. Replying to emojis, stickers, or simple compliments burns LLM tokens and looks like an automated spam bot.
- **Ignore / Skip (0 Tokens):** Emojis, stickers, compliments ("👍", "ขอบคุณครับ", "555"), spam, trolls.
- **Reply Selectively:** Filter for genuine high-intent questions (e.g. "ซื้อที่ไหน", "มีขั้นต่ำเท่าไหร่").
- **Cap:** Limit to 3-5 high-value responses per post to trigger Meta's "meaningful social interaction" boost while keeping LLM costs under 0.05 THB per post.
